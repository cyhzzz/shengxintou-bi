# 省心投 BI · 前端/全栈改造清单（v2 新表接入）

> 状态：规划文档，未写代码。确认后据此实施。

## 〇、改造分层与前提

| 层 | 文件/目录 | 现状 | 改造动作 |
|---|---|---|---|
| M 模型层 | `backend/models/`（当前为空） | 新表无 ORM 模型，ETL 用 pandas 直落 | **前提**：为 9 张新表建 ORM 模型（或 `db.metadata` 反射） |
| Q 查询层 | `backend/routes/data/`（13 文件） | 621 处旧表引用，仍查旧表 | 把查询改写为查新表，响应格式对齐前端类型 |
| V 视图层 | `frontend-react/src/` | 页面连旧表，读不到新数据 | 端点不变，组件 + `@/types` 适配新字段 |

> ⚠ **M 层是硬前提**：不建模型，Q 层改无可改。建议第一步只做 M 层 + 一个端点（如 `/dashboard/core-metrics`）打通验证，再批量推进。

## 四、System 管理页处理决策

`dim_account` / `dim_vendor` 现在是**由 Excel 导入维护的维度**（替代原两张乱 mapping 表）。两个管理页有二选一：
- **A（推荐）**：改为对 dim_account/dim_vendor 的 CRUD（保留人工微调能力）；
- **B**：下线管理页，维度完全由 `数据源/` 导入维护，界面提示"维度随聚合层导入更新"。

> 周报导出（`EmployeeConversion/Weekly/`）依赖员工转化数据，接 `agg_daily_channel_open` 后同步验证。

## 六、风险与验证

- **字段名差异**（已记录）：内容平台列叫 `平台来源`（非"平台"）；`0.1` 渠道类别用"互联网引流"等；应用市场 `oppo/vivo` 小写 vs 维度大写。适配时统一。
- **两套漏斗**：`/conversion-funnel` 响应必须带 `channel_category` 区分内容平台/应用市场，前端分别渲染。
- **旧表退役**：新版全级跑通、数据核对无误后，再 DROP 旧表（或保留一个版本做回滚）。
- **验证手段**：① 后端单元：直接查新表 SQL 与端点返回比对；② 前端：`npm run dev` 逐页面校验；③ 数据一致性：新表聚合值 vs 旧表原值抽样对账。
- **生产构建**：`npm run build` 仍坏（tsc 类型错误 + index.html 硬编码 dev 路径），开发期用 `npm run dev`，生产构建单独处理（见库表设计文档）。
