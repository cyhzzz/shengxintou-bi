## 五、React 错误修复（需求 5）

### 5.1 根因
报错 "Objects are not valid as a React child (found: object with keys {label, value})" 是把 Select options 对象当作字符串渲染，常见于：

| 位置 | 当前写法 | 问题 |
|---|---|---|
| `XhsNotes/List.tsx:43-45` | `[{label:'近7天',value:7}, ...]` 用于 Radio.Group | value 是数字，Radio.Button 的 value 应为字符串 |
| `EmployeeConversion/Weekly/index.tsx:27-29` | `[{label:'TOP 5', value:5}, ...]` 同上 | 同上 |
| `EmployeeConversion/Analysis.tsx:46-48` | `[{label:'全部线索', value:'all'}]` | 字符串 OK，但若传错位置（用 children 而不是 options）就炸 |
| `AgencyAnalysis/index.tsx:435` | `<Segmented options={Object.entries(METRIC_LABELS).map(...)}>` | Segmented options 必须是 `{label, value}` 但 value 类型不一致 |
| `Dashboard/TrendChart.tsx:263,283` | `Radio.Group` 数字 value | 同上 |

### 5.2 修复策略
- 全局统一 `Radio.Group` / `Segmented` 的 value 为字符串（`String(v)` 或 `value.toString()`）
- 改写为 `options={[{label, value}]}` 标准形式，不用 children
- 在公共 `components/Filter` 写个 `<SegmentedFilter>` / `<RadioFilter>` 组件统一封装，避免每个页面再写一遍

### 5.3 DataFreshness 同步修（与 §七配合）
前端 `groupLabels` 旧名 → 新名映射：
```ts
const groupLabels = {
  vendor_daily: '厂商日聚合',
  xhs_note: '小红书笔记聚合',
  fact_conv_content: '内容平台转化',
  fact_conv_appmarket: '应用市场转化',
  agg_daily_channel_open: '开户渠道分析',  // 新增
};
```
