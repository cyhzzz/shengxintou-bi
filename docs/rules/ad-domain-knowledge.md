# 投放业务领域知识

面向「智能辅助分析」类需求的领域知识底座：证券行业投放合规、互联网流量投放方法论、渠道特性，以及常见诊断问题到项目数据表的映射。做投放相关分析、报表解读或优化建议前先读本文件；业务口径红线以 [`business-invariants.md`](business-invariants.md) 为准。

> 时效说明：本文件记录行业通用机制与监管框架。平台版位、计费与准入规则随平台政策调整，引用时若与平台后台现状冲突，先联网核实再下结论；与项目实现冲突时以代码和数据为准。

## 1. 证券行业投放合规约束

所有营销策略类分析结论都受合规边界约束，输出建议时不得越过红线。

### 1.1 监管框架

- 《金融产品网络营销管理办法》（八部门联合发布，2026-09-30 起施行）：金融产品网络营销的总体框架。
- 证监会关于证券公司网上开户与第三方平台合作的相关规定（2018 年起延续）：第三方机构仅可提供技术服务，不得介入证券业务环节。

### 1.2 核心红线

1. 无资质个人不得营销金融产品；营销人员必须是持牌机构从业人员并获机构授权。
2. 第三方平台只能「一跳」直达金融机构自营平台；平台不得介入销售合同签订、资金划转、适当性测评与互动咨询。
3. 禁止开户比赛、返佣等激励式拉新。
4. 禁止夸大或误导性宣传（含收益承诺类表述）。
5. 客户数据主权归金融机构，第三方不得留存或转用营销过程数据。

### 1.3 对数据分析的含义

- 转化链路存在天然「合规断点」：第三方平台触点只能统计到跳转为止，开户在券商自营环境完成，跨平台归因存在上限；本项目分析以上游 ETL 预计算的链路口径为准，不做二次归因。
- 深层指标（有效户、入金、资产、创收）只能在自有系统闭环内统计；第三方平台回传只到浅层转化（激活/注册）。
- 金融素材审核严格，创意迭代成本高于一般行业；评估素材更换频率时应把审核周期纳入考虑。
- 输出优化建议时不得建议返佣、夸大收益、外采数据等违规手段。

## 2. 两条获客链路与指标体系

### 2.1 通用漏斗逻辑

任何流量投放的漏斗都是「展示 → 点击 → 浅层转化 → 深层转化 → 价值沉淀」。单层数值意义有限，层间比率（点击率、转化率、开口率、入金率）才是诊断核心。

### 2.2 内容平台链路（线索型）

对应事实表 `fact_conv_content`（一行一条线索）：

```text
曝光/阅读 -> 点击 -> 私信/表单留资 -> 线索 -> 客户开口 -> 有效线索 -> 开户 -> 有效户 -> 资产
```

- 分析维度：`笔记ID` / `笔记名称` / `广告代理商` / `创意ID` / `渠道类型` / `互动次数` / `广告点击日期`。
- 非存量条件：`是否为存量客户 == 0 OR IS NULL`；存量在有效线索之后剔除（详见 [`business-invariants.md`](business-invariants.md)）。

### 2.3 应用市场链路（下载型）

对应事实表 `fact_conv_appmarket`（一行一台设备）：

```text
下载 -> 激活APP -> 提交开户/注册 -> 开户成功 -> 新开户 -> 入金 -> 有效户
```

- 阶段布尔字段是渐进式的：走到后段的设备，前置阶段字段也为 1。
- 禁止 `WHERE 是否新开户 == 1` 过滤整条漏斗（漏斗变平）；存量通过「开户成功 - 新开户」体现。
- 应用市场真实获客口径强制 `渠道类型 = 互联网引流`，统一使用 `_funnel_filters`。

### 2.4 指标体系三层

| 层 | 指标 | 回答的问题 |
| --- | --- | --- |
| 量级 | 曝光、下载/线索数、激活数、开户数 | 计划跑得多不多 |
| 成本 | CPM、CPC、CPD、线索成本、户均获客成本 | 获取代价高不高 |
| 质量 | 有效线索率、开口率、开户率、入金率、户均资产、创收 | 转化效率与客户价值好不好 |

健康的计划三者平衡；只看量级或只看成本都会误判（见第 3.4 节诊断框架）。

## 3. 互联网流量投放核心方法论

### 3.1 账户结构与计划层级

典型结构：账户 → 计划/广告组 → 创意。预算与出价通常设在计划层，素材在创意层。

本项目 `dim_ad_plan_class` 是计划分析的关键维表：把每个「广告分组ID」按 `应用市场 × 版位 × 子版位 × 出价` 拆解；join 键为 `fact_conv_appmarket.广告计划ID = dim_ad_plan_class.广告分组ID`。

### 3.2 计费与竞价机制

| 计费模式 | 含义 | 典型场景 |
| --- | --- | --- |
| CPM | 千次曝光付费 | 品牌曝光 |
| CPC | 点击付费 | 落地页引流 |
| CPD | 下载付费 | 应用商店投放主流 |
| CPT | 包时段买断 | 开屏、首屏等固定资源位 |
| oCPD / oCPC | 目标转化出价：按激活/注册等深转化数据回传优化竞价 | 拉注册、拉开户 |

竞价排序本质是 ECPM 竞价：`ECPM ≈ 出价 × 预估点击率 × 预估转化率`（各平台大同小异；华为 CPD 场景为 `pCTR × CPD出价 × 1000`）。

推论：出价高但点击率低的计划拿不到量——素材质量是跑量的前提，不是加分项。

### 3.3 学习期与素材生命周期

- 冷启动/学习期：新计划通常 3-5 天模型探索期，期间频繁调出价或定向会重置学习，量级波动属正常。
- 素材衰减：CTR 随曝光累积下滑；小红书笔记自然生命周期约 3-7 天，信息流素材同理。持续上新素材是跑量纪律，不是可选项。
- 衰退信号：量级下滑 + CPM 上涨 + CTR 下滑三者同时出现时，计划进入衰退，应换素材或重建而非硬拉出价。

### 3.4 诊断黄金框架：量级 × 成本 × 质量

| 表现 | 诊断 | 常见动作 |
| --- | --- | --- |
| 高量 / 低成本 / 质量达标 | 优质计划 | 加预算、复制扩量 |
| 高量 / 高成本 | 竞价偏贵 | 降出价、收窄定向、换版位 |
| 低量 / 低成本 | 拿不到量 | 提出价、放宽定向、换版位或素材 |
| 低量 / 高成本 | 全面劣化 | 暂停并换素材重建计划 |
| 量好 / 质量差（有效线索率低） | 定向或素材与目标人群错位 | 优化定向、在落地页/表单环节前置筛选 |

预算分配原则：把预算从「边际获客成本高」的计划挪向「边际成本低」的计划；平均分配与只喂头部都是次优解。

### 3.5 素材与定向

- 素材三要素：封面/标题决定 CTR，内容结构决定转化率；金融类素材需兼顾专业感与合规表述。
- 定向四维：人群（年龄/地域/兴趣行为）、时间（时段/星期）、设备与版本、重定向（已激活/已访问人群排除或追投）。
- 时段规律：内容平台互动高峰 19:00-23:00；但金融决策类流量白天亦有价值——以本项目自身数据分时段验证，不直接套用行业结论。

## 4. 渠道特性速查

### 4.1 应用市场（商店投放）

| 市场 | 计费特点 | 要点 |
| --- | --- | --- |
| 华为 | CPD 为主，CPD/CPC/CPM/CPT 全支持 | 金融类主投市场：用户年龄结构偏成熟、质量好，CPD 也最贵；版位：精选推荐/全域推荐/应用搜索/焦点展台/创意推广 |
| OPPO | CPD 与 oCPD（可回传激活/注册） | 搜索广告位在联想词与搜索结果页 |
| vivo | CPD/CPT，含激励场景模块 | 推荐列表/搜索提词/红包激励/特殊准入/CPT |
| 小米 | CPD/CPC | 搜索广告位与信息流位 |
| 荣耀 | 类华为体系 | 版位逻辑与华为相近 |
| 苹果 | ASA 搜索广告（关键词竞价） | 只有搜索场景，关键词运营为核心 |

共性机制：CPD 实质是买下载量；付费占位与自然量（ASO）互补，付费推高排名通常带动自然下载。鸿蒙（HarmonyOS NEXT）生态独立后在本项目单列为一类。上表为行业通用机制，具体版位与准入以平台后台为准。

### 4.2 小红书（KFS 模型）

KFS = K（KOL/KOC 种草）+ F（Feeds 信息流放大）+ S（Search 搜索收割）三位一体，投放平台为聚光：

- K 层金字塔（行业经验值，非硬标准）：头部达人造势约 30% 预算、腰部铺量约 50%、KOC/素人真实口碑约 20%。
- F：信息流 oCPC 出价，负责放大优质笔记。
- S：搜索流量占平台大头、金融搜索需求增长快；对券商开户这类高决策成本产品，搜索是收割主战场——笔记标题与正文埋词直接影响搜索曝光。

运营参考阈值（诊断参考，非硬标准）：笔记 CTR ≥3% 算健康，<2% 优先换封面/标题；互动率 ≥5% 有爆款潜质；冷启动 3-5 天学习期勿频繁调价；活跃高峰 19:00-23:00。

行业背景：小红书高净值人群渗透率高于其他内容平台，金融行业投流为邀约制 + 风险保证金；券商内容趋势是投教「去晦涩化」。

### 4.3 渠道比较的正确姿势

本项目数据中，应用市场（oppo/vivo/荣耀/小米/华为/鸿蒙/苹果）与小红书是数据最齐全的两个分析主场。渠道强弱比较必须分层：量级层（`fact_plan_daily`）、漏斗效率层（`fact_conv_appmarket` / `fact_conv_content`）、价值层（资产/创收）——单层排名都会误导资源分配。

## 5. 诊断问题 → 数据支撑映射

做「智能辅助分析」需求时，先在此表对齐数据支撑，再写代码。

| 分析问题 | 切入维度 | 核心表与字段 | 口径提醒 |
| --- | --- | --- | --- |
| 近一个月计划跑得如何 | 计划 × 日 | `fact_plan_daily`（全渠道计划级日表）+ `dim_ad_plan_class`（版位/子版位/出价） | 平台字段归一化小写；区分应用市场与内容平台两类计划 |
| 哪个渠道跑得好/要加强 | 平台 | `fact_plan_daily.平台` + `agg_vendor_daily` | 三层比较：量级/效率/价值 |
| 版位效果如何 | 版位/子版位 | `dim_ad_plan_class` join `fact_conv_appmarket.广告计划ID` | 维表以「广告分组ID」为映射键 |
| 小红书哪些笔记好 | 笔记 | `agg_xhs_note`（笔记ID/标题/类型/账号/链接）+ `fact_conv_content.笔记ID` | 好笔记 = 互动量 × 有效线索率 × 后续资产；单看互动会误判 |
| 哪个代理商强 | 代理商 | `dim_account`（agency_name/short/letter）+ `fact_conv_content.广告代理商` | 分代理看线索量/有效率/开户率/户均资产；量级与效率分开排名 |
| 漏斗哪一步流失最重 | 阶段比率 | `fact_conv_appmarket` 布尔链 + `fact_conv_content` 链路字段 | 禁止用「是否新开户 == 1」过滤整条漏斗 |
| 获客成本多少 | 成本 | `agg_vendor_daily` / `fact_plan_daily` 对比漏斗结果 | 消费与转化口径对账见 [`business-invariants.md`](business-invariants.md) |
| 渠道开户结构 | 渠道类别 | `agg_daily_channel_open`（互联网引流/合作机构/自然流入/员工开户） | 四类业务口径不可混算 |

## 6. 术语表

| 术语 | 含义 |
| --- | --- |
| CTR | 点击率 = 点击 / 曝光 |
| CVR | 转化率 = 转化 / 点击 |
| CPM / CPC / CPD / CPT | 千次曝光 / 单次点击 / 单次下载 / 包时段 计费 |
| oCPD / oCPC | 目标转化出价：按激活、注册等深转化回传数据优化竞价 |
| ECPM | 千次曝光期望收益，流量竞价排序依据 |
| ASO | 应用商店优化（自然排名）；与 CPD 付费互补 |
| ASA | Apple Search Ads，苹果应用商店搜索广告 |
| KFS | 小红书 KOL + Feeds + Search 组合投放模型 |
| KOC | 关键意见消费者（素人向达人） |
| 冷启动 / 学习期 | 新计划的模型探索期，量级波动大且忌频繁调整 |
| 开口 | 线索产生实质咨询互动的质量标志 |
| 有效线索 | 经开口确认等质量筛选后的线索（项目口径见 [`business-invariants.md`](business-invariants.md)） |
| 有效户 | 满足入金等深度条件的账户（项目口径见 [`business-invariants.md`](business-invariants.md)） |
| 归因 | 把转化结果分配给触点/渠道的方法；本项目以上游 ETL 预计算口径为准，分析层不做二次归因 |
